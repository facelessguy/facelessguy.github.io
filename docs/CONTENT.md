# Материалы для первого выпуска

Сайт готовит витрину для работодателей РФ. На момент реализации папка `sources/` пуста, а три исходных Markdown-файла содержат только заготовки. Они переведены в `draft`: сайт не выдаёт их за настоящие работы.

## Что предоставить

1. Имя и фамилию, рабочий email, короткую биографию и профессиональные ссылки.
2. Три существующие работы: название, год, задача, аудитория, ограничения, ваша роль, принятые решения и результат.
3. Для каждой работы — обложку, 2–5 скриншотов при наличии, разрешённую к публикации ссылку на код. Не указывать командный результат как индивидуальный.
4. Для хотя бы одной работы — самостоятельный HTML5/iSpring-экспорт или URL доступного приложения. SCORM-пакет сам по себе не гарантирует работу без LMS.
5. Домен и Cloudflare Pages-проект для публикации.

Если измеримых результатов нет, опишите наблюдаемый результат и ограничения: что удалось проверить и что пока неизвестно. Числа не добавляются для убедительности.

## Профиль

Заполните `src/config/profile.ts`. Пустые контакты скрываются; адреса-заглушки не используются. Формулировка позиционирования находится рядом. «Практика» — временное название витрины, автоматически заменяется именем после заполнения.

## Новый кейс

Скопируйте `docs/templates/project.md` в `src/content/projects/<slug>.md`. Slug: строчные латинские буквы, цифры и дефисы. Сначала оставьте `status: draft`.

Обложку и изображения размещайте в `public/media/<slug>/`. Подготовьте изображения WebP/AVIF подходящего размера: до 1600 px для обложки, с сохранением читаемости интерфейса. В `cover` укажите настоящий размер, путь и содержательное описание. Не растягивайте маленькие изображения.

- `draft`: отсутствует в каталоге, HTML-страницах и данных клиентских компонентов.
- `coming-soon`: карточка видна, ссылки на кейс, демо и код отсутствуют. Текст Markdown не публикуется.
- `published`: доступен подробный кейс; обязательны роль и обложка.
- `featured: true`: работа отображается на главной, максимум шесть.
- `kind: experiment`: опубликованная работа появляется также в лаборатории и включает пункт навигации.
- `disciplines`: один или несколько тегов Product, Development, E-learning, LMS, Automation, AI.
- `demo`: slug страницы демо. `links.live` используйте для самостоятельного приложения, если отдельного описания демо нет. При наличии `demo` приоритет у него.

Все ссылки на внешние приложения — HTTPS. Кнопки запуска открывают новую вкладку. Markdown обрабатывается как доверенный авторский контент: не вставляйте сторонние скрипты.

## Новое демо

Скопируйте `docs/templates/demo.md` в `src/content/demos/<slug>.md`. Разместите самостоятельный экспорт в `public/demo-assets/<slug>/`; например, `launch: /demo-assets/course/index.html`. В `project` укажите slug опубликованного кейса, в кейсе — slug демо.

Папка экспортированного курса должна сохранять исходную структуру. Проверьте медиа, шрифты, относительные пути, кнопки, мобильное управление и возврат в кейс. Один файл не должен превышать 25 MiB. Используйте только материалы, которые можно опубликовать. Данные чернового курса не храните в `public/`: вся эта папка попадает на хостинг независимо от статуса Markdown.

`completionSupported` по умолчанию `false`. На статической стадии аналитики нет. Не включайте этот признак, пока реальный курс не выдаёт проверяемый сигнал завершения и не реализован соответствующий серверный этап.

## Готовность к публикации

`npm run release:check` проверяет имя, email, биографию, реальный SITE_URL, минимум три опубликованных избранных кейса и одно демо, полноту разделов кейса, связи и локальные файлы. Обычная сборка разрешает незаполненный сайт для локальной работы.

Ручная финальная проверка: достоверность кейсов, личный вклад, разрешения на изображения, работа реального демо, правильность контактов, доступность из целевых сетей РФ. Автоматическая проверка не может подтвердить эти факты.
