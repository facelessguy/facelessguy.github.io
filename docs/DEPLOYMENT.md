# Публикация статического сайта

Выбран Cloudflare Pages. Прямой доступ к аккаунту и целевому GitHub-репозиторию ещё не настроен. Публичная публикация должна пройти проверку готовности контента.

## GitHub и Cloudflare Pages

1. Создайте пустой GitHub-репозиторий и задайте его как `origin` локального репозитория. Не загружайте `.env`, `sources/`, сборки или служебные файлы редактора в публичный репозиторий. Технические примеры в `tests/fixtures` нужны для проверок; их сборку `.test-dist` нельзя публиковать как сайт.
2. Создайте Cloudflare Pages-проект для прямой загрузки. В этом варианте GitHub Actions отвечает за деплой; не включайте второй автоматический деплой через Git integration одновременно.
3. Добавьте переменные GitHub Actions: `SITE_URL` — реальный HTTPS origin без пути, `CLOUDFLARE_PAGES_PROJECT` — имя созданного Pages-проекта.
4. В GitHub environment `production` добавьте секреты `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`. Токену нужен доступ к Cloudflare Pages только выбранного аккаунта. Значения секретов не записываются в репозиторий.
5. Workflow `Verify portfolio` проверяет изменения. `Publish to Cloudflare Pages` публикует `dist` при push в `main` или ручном запуске, только когда переменные заданы и прошла проверка готовности контента.
6. Подключите домен через Cloudflare Pages и обновите `SITE_URL`. Повторите сборку: canonical, sitemap и социальные ссылки используют этот адрес.

Среда: Node 24 из `.nvmrc`, `npm ci`, `npm run build`, каталог результата `dist`. Конкретные версии зависимостей закреплены в package.json и package-lock.json.

Альтернатива, если нужен встроенный Git integration Pages: команда сборки `npm run release:check && npm run build`, выход `dist`, переменная `SITE_URL`, Node 24; отключите workflow публикации, оставив workflow проверок.

## До появления домена

Не задавайте `SITE_URL`: preview получает `noindex, nofollow`, robots.txt запрещает индексацию, canonical и sitemap не создаются. Не подставляйте фиктивный домен. Обновление `SITE_URL` требует новой сборки.

## После публикации

Проверьте HTTPS и все ключевые переходы на опубликованном адресе, реальный почтовый контакт, метаданные, демо и медиа. Выполните проверку из сетей целевой аудитории РФ. Локальная проверка этого не заменяет.

Для отката выберите предыдущий успешный production deployment в Cloudflare Pages. Старые адреса кейсов сохраняйте; при изменении slug добавляйте точечные 301-перенаправления в `public/_redirects`.

## Текущий статус

Локальный Git и workflows подготовлены. Удалённый репозиторий, облачный проект, секреты, домен и публичный деплой не созданы. Публикация ожидает реальные материалы и настройки аккаунта.

Основа настройки: [официальное руководство Cloudflare по Direct Upload и GitHub Actions](https://developers.cloudflare.com/pages/how-to/use-direct-upload-with-continuous-integration/).
