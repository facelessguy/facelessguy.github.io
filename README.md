# Практика — портфолио

Русскоязычная витрина на Astro, TypeScript и React: главная, каталог, подробные Markdown-кейсы, страницы запуска демо и лаборатория. Дизайн строится вокруг перехода от задачи к работающему продукту.

## Текущий результат

Реализованы страницы, адаптивное оформление, локальные шрифты Manrope, фильтры, состояния публикации, SEO, проверки контента и workflows для GitHub/Cloudflare Pages. Исходные примеры переведены в черновики. Реальные работы, контакты и экспорты пользователь ещё не предоставил; публичный запуск ожидает эти материалы.

Backend не подключён: по плану аналитика и VPS следуют за готовностью первого выпуска. Детали — в `docs/NEXT-STAGES.md`.

## Разработка

Node 24 (см. `.nvmrc`).

```sh
npm ci
npm run dev
npm run build
npm run preview
```

Без `SITE_URL` сайт не индексируется. Для production задайте реальный HTTPS origin переменной окружения. Для локальной работы можно скопировать `.env.example` в `.env`: сборка и проверка контента прочитают его автоматически.

## Проверки

```sh
npm test
npm run test:site
npm run build
npm run release:check
```

`test:site` собирает изолированные технические примеры в `.test-dist`, проверяет маршруты, связи, локальные ресурсы, canonical и отсутствие черновиков. Примеры находятся только в `tests/fixtures` и никогда не попадают в обычный `dist`. Для повторной ручной проверки их можно раздать отдельным локальным статическим сервером.

`release:check` намеренно не проходит до добавления настоящих материалов и домена. Не отключайте его в production workflow.

## Контент и эксплуатация

- `docs/CONTENT.md` — какие материалы нужны и как их добавить.
- `docs/templates/` — шаблоны кейса и описания демо.
- `docs/DEPLOYMENT.md` — настройка GitHub Actions, Cloudflare Pages, домена и откат.
- `docs/NEXT-STAGES.md` — условия запуска аналитики и VPS.

Markdown хранится в `src/content/projects` и `src/content/demos`. Публичные изображения и самостоятельные HTML5-экспорты размещаются в `public/media` и `public/demo-assets`; всё в `public/` доступно посетителям независимо от статуса Markdown. Встроенный SCORM 1.2 пакет мини‑LMS хранится в `src/scorm` и попадает в статическую сборку только вместе с опубликованной записью демо. Не кладите черновые материалы в `public/`.

`sources/` — синхронизируемые справочные материалы, только для чтения; они не редактируются и не публикуются автоматически.
